# 光室 · 收集光，也收藏时间

**[直接下载 0.6.0 调试 APK](https://raw.githubusercontent.com/02Caesar/guangshi/main/downloads/guangshi-0.6.0-debug.apk)** · [仓库](https://github.com/02Caesar/guangshi)

原生 Android 胶片相机。Kotlin、Jetpack Compose、CameraX；Android 10 及以上。针对 OPPO Find X8s+ / ColorOS 的普通竖屏设计。拍摄、实时滤镜、暗房与导出全部在本机完成，不请求网络权限，不需要登录。

## 0.6.0：紧凑机身与十款胶片

- 快门独立居中；底片盒入口左下、金属拟物转盘右下。转盘拖动切换十档胶片，点按打开完整胶片列表。
- 默认仅显示方框内的小号 EV 入口。单击展开二级参数面板，双击在 EV / 光圈 / 色彩 / 颗粒间循环并展开。刻度浮在画面上，保留 0.1 步进与实时效果，点击「收起」退出。
- 焦段倍率外观缩到 34dp 高、10sp 字号；点击显示毫米数，1.5 秒后恢复倍率，24/28/35 和 73/85 循环保持。
- XPAN 使用独立全屏机身页，隐藏常规标题和系统栏，系统手势可临时唤出。右下角胶卷按钮打开二级胶片菜单；窄长取景保持 24:65（横拍 65:24），完整原片与显影流程保留。
- 新增柔粉晴空、森绿漫游、蓝调时刻、落日金橙，合计十款。每款有独立的 RGB 曲线和颗粒默认值，GPU 取景和 CPU 导出共同实现；已有底片枚举编号兼容。

## 0.4.0：底片多选删除与恢复

暗房点击「管理底片 · 多选删除 / 回收站」，点选多张或全选，确认后移入回收站。切换「回收站」同样可多选恢复。底片盒为空时仍有管理入口。

原始 JPEG 与调色参数均留在本机，重启后仍可恢复；本版不会自动清空回收站，因此删除不释放原图空间。已导出到系统相册的照片不受影响。卸载或清除应用数据会删除私人底片，请覆盖安装升级。

如果手机无法连接 raw.githubusercontent.com，可下载 [备用 ZIP](https://codeload.github.com/02Caesar/guangshi/zip/refs/heads/main)，解压后打开 downloads/guangshi-0.6.0-debug.apk。

## 0.3.0：更大的取景框与更快的预览

- Android 13+ 优先使用 CameraX 原生 Preview（TextureView）与 GPU RuntimeShader，目标 30 fps；移除了这条路径上逐帧 RGBA 读回、旋转 Bitmap、CPU 逐像素处理和 Compose 图片更新。效果参数变动直接重建 RenderEffect，可在当前画面上更新，不等待 CPU 处理下一帧。
- 「曝光 / 颗粒 / 色彩 / 光圈」移到顶部；刻度尺浮在取景画面上，不再挤小取景框。普通竖屏按接近全宽的 3:4 画面显示，焦段按钮位于取景框内下沿，底部保留转盘、快门和底片入口。
- 曝光 -3.0～+3.0 EV、颗粒 0～1、RGB -1～+1、模拟光圈 1.4～16，均为 **0.1 一格**。可拖动、点刻度，或点击 ＋／− 微调；16 表示关闭模拟虚化。旧底片参数保持兼容，新调节吸附到 0.1。
- 删除截图红圈内的「24 ↻ 28 / 35、73 ↻ 85」常驻提示，焦段点按循环本身仍保留。
- Android 10～12 或无法创建 GPU 效果时保留旧 CPU 实时处理路径，不保证获得相同的响应改善。
- GPU 预览与 JPEG 导出使用相同色调和曝光参数。颗粒的具体纹理、虚化采样为快速预览近似，不能保证与高分辨率 JPEG 逐像素相同。仍未测量 OPPO 真机帧率或触控到显示延迟。

## 已有功能

- 正常拍摄 + 5 种胶片：原生、暖日光、冷夜景、银盐黑白、褪色记忆、青橙电影。转盘 6 档吸附、轻微触感，也能直接点选滤镜。
- **取景框显示实时效果**：Android 13+ 在原生连续取景上使用 GPU 滤镜，曝光、颗粒、RGB、模拟光圈随设置变化；拍摄保存原始 JPEG 和当时的效果参数。
- **暗房边拖边变**：大图固定在控件上方，底片横滑；曝光、反差、饱和度、冷暖、RGB、颗粒可调。按住对比原片，重置恢复默认值。黑白不应用 RGB、饱和度和冷暖。
- 焦段按钮为 **15 / 24 / 49 / 73 / 146 mm**。反复点当前 24 档循环 **24 → 28 → 35 → 24**；点当前 73 档循环 **73 → 85 → 73**。
- **模拟光圈**：ƒ/1.4～16（0.1 步进）与常用档快捷选择。点击画面选择清晰区域，外围渐变虚化，取景、暗房和导出使用相同参数，预览虚化使用快速近似。
- 深炭色机身、暖纸色快门、琥珀刻度与暗红暗房；系统安全区域留白，小窗口支持滚动。
- 修复原图导出 `divide by zero`：旧版把 `Int.MAX_VALUE` 乘以 2 造成溢出，采样循环最终除以零；现使用 Long 边界计算并校验照片尺寸。导出异常时保留原片，清理未完成的相册记录。

下载 APK 后在手机中打开，按 ColorOS 提示允许该来源安装。0.3.0 的包名仍为 `com.guangshi.app`，versionCode=3，与此前交付的 0.1.0 / 0.2.0 APK 使用相同调试签名，**请直接覆盖安装，不要先卸载或清除数据**。旧底片 JSON 字段兼容读取，升级不会主动删除照片。

## 拍摄与暗房

1. 首次打开允许相机权限；拒绝后可以重试或进入系统设置。
2. 拨转盘选滤镜、点焦段；选「曝光 / 颗粒 / 色彩 / 光圈」展开调校。取景实时显示效果，原生预览尺寸由 CameraX 协商；成片处理使用原始分辨率。
3. 点击画面进行自动对焦并指定模拟光圈清晰区域；点击快门。等待保存完成后可继续拍摄。
4. 最近照片或「暗房」进入底片盒；选片，选择滤镜与调校类别，拖动刻度尺，大图持续刷新。参数在松手、切片和离开暗房时保存。
5. 选择是否附带黑色胶片边框，点击「冲印 · 导出到系统相册」。成功后在 **Pictures/光室** 查看 JPEG。原片始终单独保存在应用私有目录，不会被调色或导出覆盖。

## 焦段和光圈的实际边界

焦段显示为 **35mm 等效值**，从 Android Camera2 报告的传感器尺寸和物理焦距估算，存在取整和有效传感器区域误差，不是直接设置镜头物理毫米数。应用会在系统开放的后置镜头中选择合适镜头，再应用 CameraX 支持的变焦；高倍率可能是数码裁切，状态行会标注。

**无法用数码裁切把主摄变成更广的镜头。** 如果 ColorOS 没有向第三方应用开放超广角或相应缩放范围，15mm 会置灰；长焦也取决于系统开放情况。点击取景框下方的镜头状态 ⓘ，可以查看本机实际报告的镜头、变焦范围与物理光圈。不能保证第三方 CameraX 能调用 OPPO 自带相机的全部镜头。

模拟光圈是 **以点击位置为中心的区域虚化**，不是人物分割或深度估计，不控制手机固定物理光圈，也不改变真实进光量或光学景深；可能把同平面边缘一同模糊。关闭时不加虚化。当前未核实 OPPO 官方规格页：云端访问官网被网络策略拒绝，因此没有把未经核实的 Find X8s+ 参数硬编码进应用。

## 构建

JDK 17 或 21，SDK Platform 35、Build Tools 35.0.0。Gradle Wrapper 8.9（固定 SHA-256）、AGP 8.7.3、Kotlin 2.0.21、CameraX 1.4.1。设置 ANDROID_HOME 或在不提交的 local.properties 中设置 sdk.dir。

```sh
sdkmanager "platforms;android-35" "build-tools;35.0.0" "platform-tools"
./gradlew --no-daemon :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.guangshi.app/.MainActivity
```

APK：`app/build/outputs/apk/debug/app-debug.apk`。Windows 使用 gradlew.bat。源码、Wrapper 和 CI 工作流都在仓库中。

GitHub 手动构建：**Actions → 光室 Debug APK → Run workflow → main**；成功后下载 Artifacts 中的 `guangshi-debug-apk` ZIP，解压获取 APK。报告在 `guangshi-check-reports`。工作流使用 Ubuntu 24.04 自带 SDK，移除了上次失败的 SDK 初始化 Action。
